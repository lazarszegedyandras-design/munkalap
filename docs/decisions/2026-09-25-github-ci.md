# GitHub CI a main ághoz

## Helyzet

A `main` ág már pull requestet kér, de automatikus teszt nélkül hibás módosítás is összevonható. A teljes Docker-alapú release acceptance külön folyamat, amely helyben sem futott még végig.

## Döntés

A `.github/workflows/ci.yml` minden pull requesten és a `main` ágra kerülő commiton két ellenőrzést futtat: a backend pytest tesztjeit Python 3.12 alatt, valamint a webes kliens Node 20 tesztjeit és buildjét. A backend teszt ideiglenes SQLite-adatbázist és futásidejű mappát használ. A workflow csak `contents: read` jogosultságot kap, és nem használ éles adatot vagy titkot.

Miután az első pull requesten mindkét job sikeresen megjelent, a GitHub ágvédelemben a `Backend tests` és a `Frontend tests and build` ellenőrzés kötelezővé válik.

## Következmények

Ez gyors visszajelzést ad a forrásváltoztatásokhoz, de nem váltja ki a Docker-alapú teljes release tesztet, a production ellenőrzést és az adatbázis-felügyeleti teszteket. A privát forrásadatok továbbra is a Git-tárhelyen kívül maradnak.
